## ① 術式プロファイル照合(週次フィードバック)

### 目的

自分が実際に行っている術式について「最近こうしたほうがよいと report されている」
「こういう良くない面が報告されている」を週次で拾い、知識更新の検討材料にする。

### 前提として必要なもの

**術式プロファイル**。これは推測で作ってはならない(無関係な警告と見逃しが出るため)。
本人からの申告が必要。想定する粒度:

| 領域 | 記述する内容 |
|---|---|
| 膝 | セメント/セメントレス、PS/CR、アライメント手法(mechanical/kinematic/functional)、ロボット・ナビの使用、膝蓋骨置換の有無 |
| 肩 | リバースの設計(inlay/onlay、lateralization、glenosphere径)、stemlessの使用、subscapularisの処理 |
| 腱板 | single row/double row、SCR併用の有無、使用アンカー |
| PRP | 製剤(ACP/ACPMAX/Angel)、適応疾患、投与回数・間隔 |

### 拾う対象(本人の選択により4種すべて)

1. 合併症・有害事象の報告(感染、脱臼、緩み、骨折など)
2. revision率・生存率の低下(中長期成績が従来より悪いという報告)
3. ガイドライン・推奨の変更(学会声明、コンセンサス、診療ガイドライン更新)
4. 新しい術式・優位性の報告(従来法より良好な成績)

### 設計方針(重要)

- **判定はせず提示にとどめる。** 「この論文は◯◯という術式に言及し、
  5年revision率について報告している(PMID: xxx)」まで。
  「変更すべき」とは言わない。仕様の「臨床判断は行わない」を維持する。
- **必ず元の抄録へのリンクを付ける。** 振り分け自体はLLMが行うため誤りうる。
  見逃しも誤検出もある。「スクリーニングの補助であって網羅の保証ではない」
  という位置づけを出力にも明記する。
- **抄録に無い数値を書かない。** これは既存の実装方針と同じ。
- 出力先は週次ノートの冒頭に「今週の要注意」セクションとして追加する。
- 週次で取得済みの抄録を読むだけなので、PubMedへの追加リクエストは不要。

## ② 都度検索(難症例向け)

### 目的

その場でPubMedを検索して抄録を手元に置き、相談の材料にする。

### 想定するインタフェース

```
python3 -m arthroplasty_watch ask "patellar instability after total knee arthroplasty"
```

- その場でPubMedを検索し、抄録付きでvaultに書き出す(原文のまま)
- 定型トピックとは別フォルダに置く(週次の差分抽出を汚さない)
- 本人の情報が不要なため、いつでも着手できる
